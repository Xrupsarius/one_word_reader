# Viewreader

Оформление обновлено: тёплая светлая и приглушённая тёмная темы, отдельная панель чтения, настройки сбоку на широком экране и под чтением на телефоне. Библиотека отображается карточками, текущая книга отмечена цветом ORP. Используются системные шрифты и Charter/Georgia для книжного текста; внешние шрифты и дополнительные UI-зависимости не нужны. Проверены ширина 360 px, увеличение текста до 200%, обе темы, клавиатура и работа библиотеки.

Клиентская RSVP-читалка. React выбран для разделения экранов и состояния; движок — независимый TypeScript без DOM. Исходный прототип сохранён в `rsvp-reader.html`.

## Запуск

Нужен Node.js 22.13+ (проверено на Node.js 26) и npm.

```sh
npm ci
npm run dev
```

Открыть адрес из терминала (обычно `http://localhost:5173`).

```sh
npm test
npm run build
npm run preview
```

`npm run build` проверяет strict TypeScript и создаёт `dist/`. Для будущего Capacitor используется относительный Vite base.

## Этап 1 — готово

- TXT в UTF-8, импорт и токенизация в отдельном Web Worker; кнопка и перетаскивание файла.
- Вставка собственного текста и демонстрационный текст из прототипа.
- Чистый TypeScript RSVP-движок: 60000/WPM, паузы ×2.2/×1.6, длинные слова ×1.3/×1.5, ORP по прототипу.
- Пауза, продолжение с текущего слова, переходы между предложениями, ползунок позиции и оценка времени с учётом пауз.
- Таймер с абсолютными сроками: корректирует небольшой дрейф, после длительного зависания не пролистывает слова пачкой. При скрытии вкладки чтение останавливается.
- Скорость 100–1000 с шагом 25, размер шрифта, три темы, разгон от 60% до 100% за 5 секунд, отключение пауз на пунктуации. Настройки сохраняются в localStorage, книги и позиции — в IndexedDB.
- Русские строки в `src/i18n/ru.ts`, safe-area, видимый фокус, кнопки от 44 px, reduced-motion.
- Пробел — чтение/пауза, ←/→ — предложение, ↑/↓ — ±25 WPM. В полях и кнопках сохранено нативное управление клавиатурой.

Проверено: 35 тестов Vitest, production-сборка, Chromium на 360 px и 1280 px: импорт Worker, восстановление настроек, ошибка парсинга, ввод текста, кнопки и горячие клавиши.

TXT с другой кодировкой показывает просьбу сохранить файл в UTF-8. Для MOBI/AZW выводится сообщение о конвертации в EPUB.

## Этап 2 — готово

- EPUB: JSZip, метаданные OPF, порядок по spine, относительные пути, пропуск нелинейных элементов, понятная ошибка DRM.
- FB2: UTF-8, windows-1251 и UTF-16 по BOM, метаданные, вложенные разделы как отдельные главы; примечания и бинарные изображения исключены.
- XML обрабатывается DOMParser из `@xmldom/xmldom`: браузерный DOMParser недоступен в Web Worker. Скрипты не выполняются, сетевые ресурсы книги не загружаются.
- Распаковка, парсинг и токенизация выполняются в Worker. UI получает готовую структуру без знания формата.
- Книга и подготовленные слова сохраняются в IndexedDB через idb; позиция обновляется при каждом слове. При открытии восстанавливается последняя книга, то же слово, на паузе.
- 41 тест: небольшие EPUB/FB2, реальный файл windows-1251, spine, очистка разметки, повреждённые файлы и XML-сущности.

Проверка в Chromium на этой машине: синтетические EPUB/FB2 по 162000+ слов (примерно 500–650 страниц при 250–300 словах на страницу), 60 глав. Импорт 357/318 мс, максимальный интервал между кадрами 117/100 мс; после закрытия вкладки оба восстановились с позиции 1234 (нумерация с нуля). Это локальное измерение, не гарантия времени на телефонах. Сборка и тесты прошли.

## Структура

```text
src/domain/    # Book, Chapter, настройки
src/parsers/   # parse(file) → Book
src/workers/   # импорт и подготовка слов
src/engine/    # таймер, ORP, задержки, навигация
src/storage/   # IndexedDB: книги, метаданные и позиции отдельно
src/ui/        # React
src/i18n/      # строки интерфейса
src/styles/    # темы и адаптивная раскладка
tests/fixtures/# небольшие тестовые книги
```

## Этап 3 — готово

Библиотека показывает название, автора и процент чтения. Можно открыть сохранённую книгу, продолжить с её позиции и удалить. Метаданные и позиции хранятся отдельно от текста: список не загружает все тексты в память. Добавление — кнопкой или drag-and-drop. При удалении активной книги экран возвращается к демонстрационному тексту.

Проверено в Chromium: пустая библиотека, два импорта, переключение между книгами, независимые позиции, закрытие/открытие, выбор главы, удаление активной книги и всех книг. 41 тест и production-сборка прошли.

## Этап 4 — готово

`vite-plugin-pwa` создаёт манифест, иконки и service worker. В production кэшируются оболочка и Worker. Приложение можно установить через меню браузера; нужен HTTPS, кроме localhost. Обновление применяется кнопкой и предварительно останавливает чтение.

Офлайн проверяется на production-сборке:

```sh
npm run build
npm run preview
```

Один раз открыть при подключённой сети, дождаться подготовки офлайн-режима, затем отключить сеть и перезагрузить. В dev-режиме service worker выключен. Книги в IndexedDB доступны без сети; очистка данных сайта удалит библиотеку. В Capacitor service worker может отсутствовать: парсеры, движок и хранилище от него не зависят.

Проверено Chromium: service worker управляет страницей, офлайн-перезагрузка восстанавливает слово EPUB, чтение и импорт нового FB2 работают без сети, манифест доступен из кэша. 41 тест и сборка прошли.

## Этап 5 — готово

- DOCX через mammoth.js: извлечение текста без изображений, документ как один раздел. Название берётся из имени файла, автор не извлекается.
- PDF через pdf.js: текст по страницам, название и автор из метаданных при наличии. PDF.js получает отдельный вложенный Worker; основной поток не разбирает PDF.
- PDF без текстового слоя показывает сообщение о необходимости OCR. OCR не выполняется. Пустые страницы в смешанном PDF пропускаются; качество порядка текста в колонках зависит от самого PDF.
- Повреждённые файлы и PDF с паролем показывают ошибку. Текущая книга остаётся доступной при неудачном импорте.
- DOCX/PDF загружаются лениво в Worker, а PWA заранее кэширует их код и PDF CMaps/стандартные шрифты. Первый офлайн-кэш занимает около 4.4 MiB до сжатия.
- Длинные слова автоматически уменьшаются до доступной ширины с сохранением ORP в центре.
- Тексты интерфейса и ошибок собраны в `src/i18n/ru.ts` и `src/i18n/parsers.ru.ts` для будущей локализации.

Проверено: 46 тестов Vitest на движок и реальные небольшие TXT/EPUB/FB2/DOCX/PDF; production-сборка; Chromium офлайн: импорт DOCX, импорт PDF с текстом, сообщение OCR для PDF без текста, сообщение конвертации для MOBI. Архивы тестов синтетические, личных книг в репозитории нет.

```sh
npm run format        # Prettier для исходников
npm run format:check  # проверка без изменений
```

PDF CMaps и стандартные шрифты автоматически копируются из установленного pdfjs-dist при `npm ci` и сборке; `public/pdf-assets/` не нужно добавлять в Git. Движок использует инъекцию таймера и не обращается к DOM. Для Capacitor достаточно подключить `dist/` как webDir; нативные проекты здесь не создавались.

Известное замечание `npm audit`: цепочка CLI-зависимостей mammoth → argparse → sprintf-js содержит advisory moderate. Этот CLI не импортируется в приложение: используется browser-сборка mammoth. Предлагаемое npm понижение mammoth до 0.3.x не применяется. Перед выпуском стоит повторить аудит и проверить обновления upstream.

Нативные Android/iOS и реальные телефоны пока не проверялись; мобильные проверки выполнены в Chromium с viewport 360 px. Все книги остаются в хранилище браузера; приложение не отправляет содержимое книг в сеть.
